# Database File Prompt

## 読むタイミング

- `Database/file/` に YAML を追加するとき
- 既存 YAML の構造や配置を変更するとき
- YAML 管理にするかコード管理にするか迷うとき

## 必須ルール

- YAML はプレイヤー操作で変化しない定義を中心に置く。
- `file/<連番>.<カテゴリ>/` の構成に従う。
- 既存カテゴリがあるなら優先して再利用する。

## 更新チェックリスト

1. そのデータを YAML 管理すべきか確認する。
2. 配置カテゴリを確認する。
3. 命名規則、参照形式、既存構造に合わせる。
4. 読み込み側コードや説明資料への影響を確認する。

## 非推奨

- 少数のコード前提定義を無理に YAML 化すること
- 既存カテゴリを無視して似たカテゴリを増やすこと
